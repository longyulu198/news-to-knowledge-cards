# News Knowledge Extract

## Overview

把粘贴的文章或本地 Markdown/TXT 文件转换为可复习的知识点卡片，每张卡片自洽，卡片之间按依赖关系连贯排列。

## Input handling

- 接受用户直接粘贴的正文，或本地 `.md` / `.txt` 文件路径；有文件路径时先用可用工具读取正文，再开始提炼。
- 若请求涉及网页抓取、PDF、Anki 或图形界面，明确说明本 Skill 不支持这些输入/输出，并请用户提供粘贴文本或 Markdown/TXT 文件。不要尝试变通实现。

## Extraction rules

- 只提取原文真正承载信息的部分：定义、机制、因果关系、数据、方法、结论、限制条件。
- 所有表述必须能在原文中找到依据。忠实转述，不补充原文没有的事实、案例、数字或结论。
- 删除套话、重复、广告、导航和修辞性铺垫；含义重叠的内容合并为一张卡片。
- 合并判定：只看核心知识是否相同。核心知识是同一结论、同一机制或同一组数据时合并；核心知识不同（不同结论、机制、条件、数据、限制或应对措施）就分开，即使它们来自同一段。段落相邻或同属一个话题不构成拆分理由。
- 按依赖顺序排列卡片：事实与背景 → 机制或因果 → 数据与效果 → 限制与风险 → 应对或建议，使整组卡片连成一条逻辑链。不必给卡片标注类别名。原文把问题与应对写成一组对照句时，若两者不是独立主张，就放在同一张卡片里，不要为了排序拆开。

## Card format

每张卡片严格使用以下结构，不要增删字段：

```markdown
### N. 标题
- 核心知识：...
- 简明解释：...
- 这个知识点能解决什么问题（它出现的意义）：...
- 例子或自测问题：...
```

- 标题：简短，直接陈述该知识点本身，不要用宽泛话题名。
- 核心知识：一句话给出一个结论；可包含支撑该结论的必要事实（数据、范围），但不要塞进第二个主张。
- 简明解释：1–3 句，补充原文给出的因果、条件、范围或后果；原文只有单一陈述时，允许用一句话把它说清，但不要扩写原文没有的因果，也不要为凑字数大段复述核心知识。
- 这个知识点能解决什么问题（它出现的意义）：写它澄清的事实或原文要回答的问题；原文没有明确用途时，只写它消除了哪种歧义，不推断额外效果。
- 例子或自测问题：原文中的同一个例子只用一次，放在核心知识直接涵盖该例子的那张卡片；其余卡片改用自测题。原文材料是数据或事实而非示例时，也用自测题。自测题必须能仅凭本卡片回答。绝不编造例子。

## Quantity and sufficiency

- 原文能支撑时输出至少 5 张卡片；不设固定上限，卡片数由原文可支撑的独立主张数决定。
- 原文不足以支撑 5 个不重复且有依据的知识点时，只输出能支撑的数量，并在全部卡片末尾加一行：`原文信息不足，仅能整理出 N 张有依据的卡片。` 不要为了凑数编造或拆分同一知识点。

## Final check

- 每张卡片的五个字段互相一致，没有自相矛盾。
- 卡片按依赖顺序排列，没有两张卡片重复同一主张。
- 每句话都能回溯到原文；无法回溯的句子一律删除。

## Output

只输出卡片（以及信息不足时的说明行），不要加前言、过程说明或额外章节。
